# A capture is an immutable, expiring result that later reads page

status: accepted (2026-10-22), prep record for the MCP 1.0 slices (A1 of the arc #214 → A1 → A2 → B, C1 → C2); amended (2026-10-23): decided during implementation; amended (2026-10-25): the apartness proof sees bind aliases between mounts

Trawl has no stable event identifier. Identical events exist, the hot buffer moves between two pages of one query, and a repin or compaction can change what a second run of the same text returns. An agent that reads a page, reasons about row 7 and then asks for "the events around row 7" needs row 7 to mean the same thing a minute later. Offset paging over `/query` re-runs the text each time, so it cannot promise that. The proposal of 2026-10-21 said a captured result "is a run result without a net" and could reuse the retained-run machinery. The tree disagrees: a report run has mandatory schedule and saved-query foreign keys (`migrations/20260913000001_initial_schema.sql`), its parquet writer is private, goes through NDJSON and `read_json` type inference so exact types are lost, writes no file for zero rows, lives under `scheduled/` inside the epoch-managed data root, and expires by days. Only its publication pattern (stage a temporary file, rename, then commit metadata) and its named missing-file outcome carry over.

## Decision

**A capture is a new server capability.** `POST /api/v1/results` executes one DSL query under every guard `/query` applies (bearer auth, the trawl grant, per-key rate, the ADR-0054 request count, the executor permit, the publication guard, the ADR-0056 scratch budget, history and the ADR-0046 timing event) and writes the result once, as an immutable typed parquet file with a Postgres row describing it. The response names the result, its bounds, its typed columns, how many rows the execution produced and how many were captured, and when it expires. `GET /api/v1/results/{id}` pages rows by row number with a column projection, `GET /api/v1/results/{id}/cells/{row}/{column}` returns one full cell by byte range, and `GET /api/v1/results` lists the caller's own unexpired captures so a client that lost a response can find what it made. Nothing in these reads runs a corpus query. The web UI and CLI gain the same capability; the MCP server (ADR-0058) is one client of it.

**A captured row is (result id, row number).** Row number is the 0-based position in the stored file's order, fixed at capture. Columns are positional, with names and types in the metadata, so duplicate display names survive. A client may hold a captured row across turns and name it to other operations (ADR-0058's `context`, ADR-0059's keeps). It is a row of a frozen copy, never an event identity: the result says when it was taken and the executed text and bounds that produced it.

**Bounds are resolved once, server-side, from one source.** A request carries either a structured window or the DSL's own `last=`, `earliest=` and `latest=`; both at once are refused. `last=` is resolved at execution time T to the half-open `[T−d, T)` in microseconds, an open end is closed at T, the default when neither is given is the last 15 minutes, and a span longer than 7 days is refused before scanning. The server splices the resolved clauses into the text in the `materialize_window` pattern of ADR-0018 and proves the rest of the query unchanged, so the recorded text is exactly what ran. `from saved` passes through as `/query` runs it today, with no bounds, and the response says so; the human declined to refuse it, because 1.1 (ADR-0035) replaces key-private runs with shared tables and nets.

**Over the cap, events are ordered and aggregates refuse.** A capture keeps at most 5000 rows or 4 MiB of wire-encoded cells (the #214 encoding of ADR-0035), whichever comes first. Plain searches emit no `ORDER BY` (only `tail` adds `_time DESC`), so a prefix of an unordered result is an arbitrary subset. An event-shaped result, one with `_time` and no aggregation, is therefore captured in `_time DESC, _ingested DESC` order and keeps the most recent rows up to the cap, with the exact total from the same execution; the recorded text carries the imposed order. A result with aggregation or projection that exceeds the cap is refused with `result_too_large` and a hint to aggregate or narrow, because a prefix of an aggregate changes its meaning. The engine's existing `max_result_rows` refusal still applies first.

**Temporary results are principal-scoped and short.** A capture without an investigation belongs to the key that made it and expires 15 minutes after creation. Another key gets 404. It survives a trawld restart until its deadline. Quotas start at 64 results and 64 MiB of file bytes per key, and 512 results and 512 MiB installation-wide; the server reserves the maximum before scanning, settles after commit, and refuses before any executor permit is taken when the reservation cannot be made. All four numbers are advertised by the capabilities route of ADR-0058 and are configuration. A capture attached to an investigation is kept under ADR-0059's evidence policy instead.

**Captures live in the results root.** `[server] results_dir` names it; the default is the data root's sibling `<data>.results`. This is the results root ADR-0035 names for table revisions and run results, with captures as its first tenant; moving report runs there stays 1.1 work. The root is 0700, its final path component is opened no-follow, it is compared by device and inode with the data root, the WAL and query scratch so it is inside or above none of them, and trawld locks it for the life of the process (ADR-0052). Files are 0600 and are published by staging on the same filesystem, syncing, renaming and then committing the metadata row. Boot deletes staged files that have no row and marks rows whose files are missing. Query scratch (ADR-0056) is not used, because boot empties it and a result promoted to evidence must not need a copy.

**Lifecycle outcomes are named, never empty.** A read of a result past its deadline or pruned by quota answers 410 `result_gone` with the reason; a committed row whose file is missing answers 409 `result_unavailable`; a file whose blake3 digest does not match answers 500 `result_corrupt` and an ADR-0040 failure event; an unknown id or another key's result answers 404. Expired rows stay as tombstones for 24 hours so the owner can tell expired from never-existed. None of these may read as an empty result or trigger a silent re-run.

**Admission is per key, and charges hold until the work stops.** At most one capture-class operation executes per key and two installation-wide, inside the executor pool, so agents cannot starve a human's Search on the default four-permit pool. A caller whose slot is busy waits inside its own deadline in a per-key queue of depth four; the fifth is refused. The deadline is 15 seconds, capped by the server's query timeout, and covers resolution, execution and the file write together. The selected cold input is bounded at 1 GiB of parquet plus the bounded hot snapshot, computed from the protected selection before execution. A client that aborts the request cancels the work the way the pool already does (`RequestGuard::drop` latches cancellation and interrupts DuckDB), and the permit, the admission slot and the quota reservation stay charged until the work physically stops. Captures appear in `/queries` and in history like any query, with the ADR-0046 kind `capture`.

**Errors carry the fix.** The error envelope is unchanged. Two additions serve every client: a 429 carries `Retry-After` rounded up from the governor's wait, which the rate limiter computes today and discards, and trawl-client surfaces `X-Request-Id` on every error so a client can quote it.

Considered and rejected:

- **Reuse report runs by manufacturing a schedule.** Runs need a schedule and a saved query, are read only by the owning key, and their files are typed by inference. A capture would carry two fake parents to satisfy storage.
- **Keep temporary captures in query scratch or in memory.** Scratch is emptied at boot and an in-memory registry dies with the process, so every restart would orphan the agent's handles and promotion to evidence would need a copy racing expiry.
- **Keep a labelled prefix of any result.** Honest for events once ordered, dishonest for `stats`, `top` or `dedup`, whose first 5000 rows are not the answer. The split rule keeps the first and refuses the second.
- **A derived event handle from `_time`, `_ingested` and a hash of `_raw`.** Identical events collide, and the handle would survive the hot buffer moving without the rows doing so. A frozen copy is honest about what it is.
- **Reuse pool query ids as durable handles.** They restart at zero at each boot (ADR-0046). Result ids are random 128-bit strings, never reused.

## Amendment: decided during implementation, 2026-10-23

Building #307 settled ten points the decision left open. The decision stands; these refine it.

- **HTTP/2.** trawld's listener stays HTTP/1.1, as ADR-0054 records. The abort evidence runs over HTTP/1.1 against the real listener, and over HTTP/2 only in a test that serves the real router behind a test listener. The HTTP/2 leg is evidenced by `crates/trawl-server/tests/results_abort.rs`, through the test-only listener `serve_with_listener_h2_for_tests`; `trawld` itself stays HTTP/1.1 (ADR-0054). Enabling HTTP/2 in production is a separate decision.
- **Read permission.** Every read, the list included, needs the trawl `query` permission and ownership of the capture. A key without `query` gets 403, and another key's capture answers 404, as an unknown id does.
- **Operator visibility.** No route shows another key's captures in this release, not even to `server_manage`.
- **`latest=` alone is refused**, in the query and in the window, because it names no start. A 15-minute span ending at `latest` was rejected: it guesses a start the caller never gave.
- **Projection is by name.** `columns` lists display names separated by commas, each name selects every column that has it, and the page lists the selected columns in stored order with their `positions`. A name that holds a comma cannot be selected alone. A cell is addressed by position, since names are not unique.
- **A cell is read by byte range in query parameters**, `offset` and `length`, over the cell's wire text, cut back to a UTF-8 boundary, with `total_bytes` and `next_offset`. HTTP `Range` and 206 were rejected: the capability is transport-free, and an in-process host has no headers.
- **The reservation is `[capture] max_file_bytes`**, 8 MiB, which is also the writer's hard cap on the file. A key needs that much free quota to start a capture.
- **A result with no columns has no file.** Its record has `file_bytes = 0` and no digest, and its reads answer empty rows without touching disk. A result with columns and no rows still has a file that holds the columns.
- **Admission refusals are 429 with `Retry-After`**: `capture_busy` names the time until the first running capture's deadline, and `capture_quota_exceeded` the time until the first temporary result in the full scope expires, capped at `ttl_secs`. Bounds refusals, `capture_source_too_large` and `result_too_large` are 400.
- **`X-Request-Id` reaches the caller on every error that got a response.** trawl-client exposes it on each such error, and the CLI prints it after the message.

The structured window spells `earliest` and `latest` as RFC 3339 instants with their offset applied, unlike the DSL's literals, whose offset `/query` drops. A missing file of a `from saved` run counts as zero bytes against the source budget; the vanished-run check then names it.

## Amendment: known limit of the apartness proof, 2026-10-23

Known limit: the apartness proof (ADR-0056's `hold_apart_from`) follows directory parents as the kernel names them and does not see bind-mount aliases; a results root bind-mounted from inside the data root is accepted. The query scratch root inherits the limit. A mount-aware proof (mountinfo or `STATX_MNT_ID`) over every held root is follow-up work. Until then the operator keeps the results and scratch roots on paths that are not aliases of a protected root's interior.

## Amendment: the apartness proof sees bind aliases between mounts, 2026-10-25

This replaces the known limit of 2026-10-23 for the case it names. Prep record for #314.

The proof keeps the walk over directory parents and adds a second ground of refusal on Linux. For each pair of a held root (the results root or the query scratch root) and a protected root it is compared with, trawld reads the mount ID of both directories with `statx`. When the two directories are in one mount, the walk over parents is already complete and trawld reads nothing more. When they are in different mounts, trawld reads `/proc/self/mountinfo` once, finds both mounts by ID, and, when they share a filesystem, compares the two directories' paths within that filesystem: the mount's root within the filesystem followed by the directory's path below the mount point. An equal, inside or above relation refuses with the existing overlap message and the mount point that exposed it. A held root that does not exist yet is compared by its nearest existing ancestor plus the missing components, so trawld makes nothing inside a protected root.

- **One mount needs no `/proc`.** Every packaged layout (the Debian unit, the chart's volume, the trial's volume) puts the roots in one mount, so the common start reads only `statx`.
- **The filesystem key is the mountinfo device, not `st_dev`.** On btrfs `st_dev` differs per subvolume within one filesystem.
- **A proof that cannot be made refuses the start.** When the kernel names no mount ID, trawld cannot tell one mount from two, so a kernel before 5.8 refuses every start that compares roots. When the directories are in different mounts and `/proc/self/mountinfo` cannot be read or is not procfs, or a mount ID has no single record, trawld also refuses with a message that names the missing capability (Linux 5.8 or later, `statx` allowed, a readable procfs). The human chose refusal over a warning: the case arises only from a hand-made mount layout.
- **Separate directories of one filesystem stay apart.** Two bind mounts of sibling directories, as a compose file with one bind per directory makes, compare as siblings and pass.

Out of scope, as operator rules in the configuration reference rather than checks: a mount made inside a root after the roots are configured (retention deletes a date directory with `remove_dir_all`, which reaches through a mount below it), aliases that only an overlayfs layer or a second mount of one network export can create, mounts changed after startup, a doctor prediction of apartness (the doctor keeps the lexical rule of `--check-config`), and platforms other than Linux, which keep the walk over parents alone. The human chose this narrow scope: only an operator with `CAP_SYS_ADMIN` can make a bind mount, so the defect guards against a configuration mistake, not an attacker.
