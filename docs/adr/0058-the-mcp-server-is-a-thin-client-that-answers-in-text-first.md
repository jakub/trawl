# The MCP server is a thin client that answers in text first

status: accepted (2026-10-22), prep record for the MCP 1.0 slices (A2 and B of the arc #214 → A1 → A2 → B, C1 → C2)

Trawl's own agentic features power features and are not a chatbot (ADR-0035's analyses keep a closed read-only tool set). The investigation of 2026 is a Claude instance speaking MCP and progressing in real time from the answers it gets. That needs a server that is good at being asked: it orients the model in one call, answers a search with a summary before rows, keeps a frozen copy the model can come back to (ADR-0057), correlates one literal across services, compares two windows honestly, and never pretends to be more than a client holding a key. Two facts shaped the design more than the proposal expected. There is no application layer in trawl-server: `handlers::query` owns permission, validation, permit, deadline, publication gate, scratch and shaping in one function, and bearer auth, the trawl grant check, per-key rate and the ADR-0054 count are middleware, so a second door inside the process would skip them. And the clients are not what the spec revision suggests: Claude Code negotiates MCP 2026-07-28 with fallback to the initialize handshake, spills any text result over 50,000 characters to a file, does not document rendering `structuredContent`, documents no consumer for per-resource `subscriptions/listen` updates, and claude.ai connectors connect from Anthropic's cloud, so a tailnet endpoint is unreachable from them regardless of OAuth.

## Decision

**The MCP server is a client.** A new library crate `trawl-mcp` holds the protocol handling, tool schemas, result shaping and a typed backend trait. Its only backend in 1.0 is trawl-client over HTTP to a trawld, so every guard the API applies, applies. Every new capability (ADR-0057's captures, this ADR's correlation reads, ADR-0059's investigations) is an `/api/v1` route first, written transport-free inside trawl-server so a later in-process host can call it behind equivalent edge checks. `trawl-mcp` never depends on trawl-server and contains no model, no SQL and no "ask trawl" tool. The 1.0 transport is stdio: `trawl mcp --profile <name>` in trawl-cli. It selects its target the way the doctor does (ADR-0047): the profile is named on the command line, the key comes from that profile's own table or `--token-file`, and an ambient `TRAWL_TOKEN`, `TRAWL_PROFILE` or `TRAWL_URL` ends the process with exit 2 naming the variable and never its value. stdout carries protocol frames only; logs go to stderr; no TUI starts. The streamable HTTP transport, trawl-web forwarding, MCP envelope admission (an amendment to ADR-0054), the `watch` and `operations` tools, and OAuth are later slices and are not promised here.

**The protocol target is dual-era.** `rmcp` is pinned to an exact version (3.7.0 at this writing) and keeps its default set of supported protocol revisions, so a 2025-11-25 client's `initialize` and a 2026-07-28 client's `server/discover` both work. The 2025-11-25 baseline is the working contract: tools with `outputSchema`, honest annotations, resources and one prompt at most. Nothing depends on per-request `_meta` being present, on `structuredContent` being rendered, or on `subscriptions/listen` having a consumer. `tools/list` is deterministic in order and carries private cache hints. Tool inputs are flat objects with an enum `mode` or `action` field and no root-level `anyOf` or `oneOf`, and property names stay within `[A-Za-z0-9_.-]`, because Claude Code drops tools that break those rules. `readOnlyHint` is true for `orient`, `fields` and `read` and false for the corpus tools and `investigation`, because a corpus tool can record a step.

**Text is the contract; structure mirrors it.** Every tool result has one text content block that stands alone, and a `structuredContent` object that mirrors it under an `outputSchema`. The text block is laid out for the model: an outcome line; the resolved bounds and executed text; four separate truncation facts (rows the execution produced, rows captured, whether the DSL itself sampled, limited or deduplicated, and whether cells were abbreviated or columns omitted); facets over the captured rows for at most three low-cardinality fields with five values each; at most two proposed next actions with arguments; the deep link; then one columns line and the rows as JSON arrays with every cell JSON-escaped, so hostile event text stays data. Responses are bounded at 16 KiB by default and 32 KiB hard, counted over the text block and the mirror together, which stays under the 50,000-character spill even if a client counts both; error text is at most 8 KiB. Rows per response default to 50 and cap at 200; a cell over 512 bytes is abbreviated with a marker and a `read` of the full cell. Hints are computed, never generated: dominance of one service or host, an empty result with the nearest bounds that hold data for the same filter, a lagging sender when `_ingested` runs far ahead of `_time`, a field never observed in that service. A failed validation is a successful call; a refused tool is `isError` with the server's code, message, a caret excerpt cut from the sent text on character boundaries, the hint, the request id and the `Retry-After` wait.

**The tool set.** `orient` answers one call with the installation: server version, now in UTC and the display zone, environments, services and hosts with 24-hour volume and last seen, retention reach, degraded pins, health, the caller's effective permissions, the applied bounds and quotas, which DSL features are installed, and the open investigations. It reads `whoami`, `health`, the schema routes and a new `GET /api/v1/capabilities`. `fields` answers the fields of a service or the columns of a captured result, each with its provenance (catalog observation, parquet footer, cached sample, this capture). `search` has a validate mode over `/validate` and an execute mode over ADR-0057's capture. `read` pages a captured result, fetches one cell, or reads an investigation. `context`, `sightings` and `compare` are below. `investigation` is ADR-0059's. The DSL reference is served as resources, sectioned under the hard cap, and `orient` carries a short essentials block for clients that read no resources.

**Deep links are built by the shared codec.** The ADR-0027 codec (`search_url`, `query_merge`, `filter_codec`, with the `Mode`, `RangeSpec` and filter types) moves into a pure library crate that trawl-web-ui depends on and re-exports; the range-dialog adapter that takes `fleet_ui::RangeValue` stays in the UI over plain strings. A link carries `q` with the executed text including exact microsecond `earliest=` and `latest=`, so the Search merger's inclusive `_time<=` can only intersect and never widen; `r` carries the whole-second hull (floor, ceil); `page` is 0; `f` and `mode` are omitted. The origin is one explicit `[server] link_origin`; with none configured, or a link over the 32 KiB admission limit, no link is emitted and the result says why. A forwarded host never chooses the origin.

**Three correlation reads, each a capture.** They are `/api/v1` routes that build DSL by typed construction with trawl-core's quoting, never SQL, and run through ADR-0057's capture with its admission, deadline, quotas and cancel-on-abort. Each records the ADR-0046 kind that names it.

- `context` takes a focus row, a captured row that carries `_time`, `env` and `host`, or an explicit scope when one is absent; a focus row without them and without a scope is refused by name, never widened to the installation. The default is 30 seconds either side on the focus row's `env` and `host`. It returns three groups separately: strictly earlier rows (default 10, at most 50), rows sharing the focus row's `_time` (at most 20), and strictly later rows (default 10, at most 50), ordered by `_time`, with the focus row shown apart. The result says it is a new read and that equal timestamps establish no order.
- `sightings` takes one literal and bounds (default the last 24 hours, at most 7 days). It runs the bare-term text search trawl already has, once, over `message` and `_raw`. Counts by service and environment, and first and last seen, are exact over every match from that execution. The 5000 most recent matches are captured, and the fields in which the literal occurs are attributed in Rust from the captured rows under the text search's own containment rule; matches found only in `_raw` are counted apart, because `_raw` can match field names and syntax. The result names both denominators ("field counts are over the N captured matches; service counts are over all M"). An explicit `fields` list restricts attribution and never selects a different population. At most two follow-up queries are proposed.
- `compare` takes one filter, a foreground window, a baseline window (default the equal-duration window immediately before) and at most two group fields. One statement scans the union hull of both windows and labels each event's membership, so both halves come from one hot snapshot and one pin snapshot; overlapping windows are refused. It returns both counts and durations, rates per duration, absolute and relative change where defined, groups new in the foreground (a zero baseline is `new_in_foreground`, never infinity), groups that vanished, and warnings when a window reaches past retention or a group field has a degraded pin. Ranking is deterministic: absolute rate change descending, then count, then group key, above a minimum count. No anomaly probability is computed from one baseline.

Considered and rejected:

- **Host the MCP server inside trawld and call the pool.** Policy and metering live in handlers and middleware, so the in-process path would skip them until an application layer is extracted. That extraction has no 1.0 consumer and is cross-cutting; it belongs with the HTTP transport slice.
- **Pin rmcp to the 2026-07-28 revision alone.** It drops every client that still sends `initialize`, including Claude Code's legacy negotiation.
- **Rely on `subscriptions/listen` to tell the model the human kept a row.** No client documents consuming it. ADR-0059 carries unseen activity inside every attached tool result instead.
- **A 64 KiB hard response cap through `anthropic/maxResultSizeChars`.** It depends on `_meta` a client may not read, and exceeds the 50,000-character spill without it.
- **Markdown tables for rows.** A pipe in event text breaks the table; JSON arrays keep hostile text structural.
- **Candidate-field fan-out for sightings.** Scanning sixteen fields separately multiplies the work of one text search and still cannot prove absence. One population, attributed afterwards, is bounded and honest about coverage.
- **Two independent queries for compare.** Ingest, compaction, retention or a repin between them would make the halves incomparable.

## Amendment: continuations make progress and requests stay inside trawld's limits, 2026-10-24

The budget fit creates the continuation a cut needs when the server page or cell range was already the last one, instead of only moving one the tool proposed. A continuation it creates must advance: when no row of a page fits, the proposed call reads that row alone at the hard cap, or its cells one at a time when no budget prints the row, and the rows block says `no row fits max_bytes N; see next actions`; a cell range with no room for a byte is an `isError` result naming the smallest `max_bytes` that prints one. Every `search` and `read` call reads trawld's capabilities once, first, and holds its page requests to `bounds.page_max_rows` and its cell requests to `bounds.max_wire_bytes`, because trawld refuses more; when the capabilities cannot be read the request goes out uncapped and trawld's answer is the refusal. A result timestamp the renderer cannot parse prints on one escaped line like every other server string. Found by the final file-granularity sweep on #308 and the clean passes over its fixes.
