## Current capabilities

Trawl collects and searches logs for homelabs and small installations on one
node. It stores events in Parquet and executes a pipeline query language with
DuckDB. The browser, CLI, and terminal UI query the server. The CLI can also
query local Parquet files without a server.

At `6cf93383`, `main` provides these capabilities:

- First run: `trawl trial up` starts a disposable trial in Docker on Linux,
  with sample data, and `trawl trial down` deletes it
  ([ADR-0045](../adr/0045-first-run-is-a-trial-the-cli-owns.md)).
- Ingest: HTTP ingest, an optional native syslog listener, and Vector
  configurations shipped under `/usr/share/doc/trawl-server/examples/vector/`
  and tested with Vector 0.57.0. Each shipped transform that derives
  `service` checks it against trawld's service-name rule and falls back to a
  marked `*-unidentified` name
  ([ADR-0053](../adr/0053-shipped-vector-configs-send-only-service-names-trawld-accepts.md)).
- Ingest preview: trawld canonicalizes a sample and reports each event's
  outcome, and stores nothing from the sample
  ([ADR-0049](../adr/0049-an-ingest-preview-canonicalizes-a-sample-and-stores-nothing-of-it.md)).
- Syslog time: an RFC 3164 timestamp with no offset is read in
  `[syslog] default_timezone`, in a per-peer zone from
  `[syslog.sender_timezones]`, or in UTC
  ([ADR-0050](../adr/0050-syslog-reads-zone-less-time-in-a-configured-zone.md)).
- Search: filters, field inspection, aggregations, a time chart, live
  queries, and export as CSV, JSON, or Parquet. The histogram above the
  results counts the whole result, not only the page on screen.
- Saved query text, scheduled reports, and stored run results. A scheduled
  report can run by hand. A saved query does not freeze its current results.
  Scheduled runs in flight are capped at `max(1, max_concurrent_queries / 2)`.
  Manual runs are capped at one per key and `max(1, max_concurrent_queries / 4)`
  across the installation
  ([ADR-0018](../adr/0018-retention-and-report-window-policy.md), amended
  2026-11-09 and 2026-11-11).
- Captures: a search can be kept as an immutable result that expires, and
  later reads page through it without running the query again
  ([ADR-0057](../adr/0057-a-capture-is-an-immutable-expiring-result-that-later-reads-page.md)).
- Agents: `trawl mcp` serves an MCP server over stdio for one saved profile,
  with eight tools and the DSL reference as resources
  ([ADR-0058](../adr/0058-the-mcp-server-is-a-thin-client-that-answers-in-text-first.md)).
- Investigations: a shared, append-only log of findings with kept evidence,
  written from MCP or the browser board, under the `investigation_read` and
  `investigation_write` permissions
  ([ADR-0059](../adr/0059-an-investigation-is-grant-visible-and-its-evidence-outlives-the-corpus.md)).
- Terminal safety: a sender cannot drive the operator's terminal through
  stored text. `trawl query`, `trawl schema`, the TUI, and trawld's live
  monitor show control, bidirectional, and zero-width characters as `�`
  (U+FFFD) or as escapes. JSON written to a terminal escapes them as
  `\uXXXX`, and JSON written to a pipe or a file keeps the exact bytes.
  CSV written to a pipe or a file keeps the control characters, but still
  prefixes a field that starts with `=`, `+`, `-`, `@`, a tab, or `|` with
  `'`, so a spreadsheet does not run it as a formula.
- Access: role-based access through Fleet keys and browser sessions.
  `trawl-web` always verifies trawld's certificate
  ([ADR-0048](../adr/0048-trawl-web-always-verifies-trawld.md)).
- Diagnosis: `trawl doctor`, `trawld --doctor`, and `trawl-web --doctor`
  each prove named checks from one place
  ([ADR-0047](../adr/0047-a-doctor-proves-named-checks-from-one-vantage.md)).
- Health: disk headroom and per-environment retention reach
  ([ADR-0042](../adr/0042-capacity-reads-as-retention-reach-not-a-countdown.md)),
  one `query_timing` event per query
  ([ADR-0046](../adr/0046-a-query-reports-its-phases-in-one-timing-event.md)),
  and one `http_failure` event per server failure
  ([ADR-0040](../adr/0040-every-server-failure-names-its-request-and-stage.md)).
  A retained event at INFO or above names a failure by its closed
  `error_class` and `cause_kind`. The error text from a driver or the
  operating system goes only to a DEBUG event, which the default filter
  does not keep (ADR-0040, amended 2026-11-09).
- Alerts: a Prometheus rule pack of fifteen alerts, in
  `monitoring/prometheus/trawl.rules.yml` and as the chart's
  `PrometheusRule`.
- Storage: a field catalog, retention controls, and backup and restore
  procedures. A search counts each acknowledged event exactly once across
  compaction and restart
  ([ADR-0041](../adr/0041-an-acknowledged-event-is-counted-exactly-once-across-compaction-and-restart.md)).
  Ingest is admitted against hot-buffer capacity
  ([ADR-0043](../adr/0043-ingest-is-admitted-against-hot-buffer-capacity.md)).
  trawld keeps its stored data owner-only
  ([ADR-0052](../adr/0052-trawld-keeps-its-stored-data-owner-only.md)).
- Request limit: `[server] max_concurrent_requests`, 32 by default, counts
  requests in progress across the listener. A request over it gets 503
  `request_limit_reached` at once. Probes have an allowance of 3, and query
  listing and cancellation an allowance of 4
  ([ADR-0054](../adr/0054-trawld-counts-requests-in-progress-against-one-server-wide-limit.md)).

## Requirements and limits

A server installation needs persistent storage and PostgreSQL for the Fleet
keystore and Trawl app-state databases. The deployment guide tests PostgreSQL
17 and 18. `trawld` owns ingest, storage, queries, and the HTTPS API.
`trawl-web` serves the browser UI and requires an API connection, a public
origin, and a persistent session key. Clients need credentials with the
required permissions and trust in the server TLS certificate.

Trawl has no clustering, sharding, or multi-tenancy. There is no published
hardware minimum or general throughput guarantee. Memory and storage needs
depend on the ingest rate, retention window, and queries. The request limit
bounds ingest body memory at `max_concurrent_requests` × (wire body + decoded
body), 1 GiB at the defaults, plus 512 MiB for argon2 checks. A single-node
installation needs its own backup and restore plan.

One known limitation ships with 1.0. A batch query whose regex runs slowly
over very long stored values can keep its executor slot, one of
`max_concurrent_queries`, for minutes after its deadline. For the slowest
regex the limits allow, the estimate from its measured cost per value is
about an hour. The query still answers with a timeout at its deadline. The
database checks for cancellation only between batches of 2048 rows, so the
work and its slot continue until each query thread finishes its batch, and
other batch queries wait for a slot meanwhile. A fix that checks for
cancellation between rows is planned for 1.1.

## Chosen launch contract

A Trawl 1.0 installation starts with fresh Trawl application state and a fresh
shared Fleet keystore. Startup refuses incompatible existing state.
[ADR-0036](../adr/0036-fresh-state-launch-baseline.md) records this decision.
A refused start leaves the refused database or corpus untouched. When the
databases pass admission and the storage epoch check then refuses the corpus,
the pending app-state migrations have already been applied. Any refused start
may also have removed group and other permissions from the storage root
directories, because trawld closes them before it admits the databases or
checks the storage epoch
([ADR-0052](../adr/0052-trawld-keeps-its-stored-data-owner-only.md)).

Coastwatch is anchored to a Trawl revision through `TRAWL_REV` in its CI. It
pins `cdd12a5c`. Right after the tag, Coastwatch moves `TRAWL_REV` to
`v1.0.0`.

The platform target is a Linux server and CLI on amd64 and arm64, with a
Debian 12 floor, and a macOS CLI on macOS 15 or newer for Apple silicon and
Intel. The chart supports `tls.mode` `auto`, an existing TLS Secret
(`secret`), and a Certificate from an installed cert-manager issuer
(`certManager`). Each platform and chart mode has a CI check in the table
above or in `chart/trawl/tests/`.

The repository, release assets, container image, and chart are public.
`anonymous-pull.yml` checks anonymous access to the image and chart on
every release.

## Query text written before 1.0

[ADR-0060](../adr/0060-a-search-stage-filter-keeps-the-operator-its-author-wrote.md)
changes what some stored query text means. It applies to saved queries,
scheduled reports, and the query text kept with investigation steps and run
results. Before 1.0, the search stage read these spellings differently:

- `!=` with a glob or a regex now excludes the pattern. `host!=web*` used to
  match `web*` hosts, and now matches every other host and events with no
  `host`.
- A regex that a group closes is a regex. `(a OR msg=/x/)` used to match the
  text `/x/`.
- A comma list honours each element's kind. `host!=web*,db` used to exclude
  the exact texts `web*` and `db`, with `web*` read as text, not a pattern.
  Now it excludes every host matching `web*` and the host `db`.
- `f!=*` now selects events missing `f`. It used to mean "has `f`".

[ADR-0062](../adr/0062-a-field-the-input-does-not-carry-reads-as-null-in-every-lane.md)
fixes a field that no event in the searched range carries. It now reads as
NULL in every lane, as the DSL reference always said. Before, batch search
returned an empty result or a 400 `unknown field`, so `f!=x` found nothing
while live tail matched every event, and `host=web1 OR nosuch=x` lost its
`web1` events. Live tail now groups absent and null keys in one null group,
and `sum` over no values is NULL, not 0. Stored query text that returned an
empty result or a 400 may now return rows.

The live tail and the `extract kv` tail now read patterns, calls, and
timestamps as stored search does. Before 1.0, these spellings answered
differently by lane:

- A glob matches bytes, as DuckDB's `GLOB` does
  ([ADR-0001](../adr/0001-streaming-eval-duckdb-parity.md), amended
  2026-11-09). In a live tail, `f=[^4]*` used to keep every value that does
  not start with `4`. Now it keeps values that start with `^` or `4` in
  every lane, as stored search always did. Write `f=[!4]*` to keep values
  that do not start with `4`. `?` matches one byte, so `é` needs `??`.
- `\d`, `\w`, `\s`, `\b`, and `\B` are ASCII in the live tail and the
  `extract kv` tail, as they are in stored search
  ([ADR-0063](../adr/0063-a-querys-regex-work-is-bounded-before-it-runs.md),
  amended 2026-11-09). In a live tail, `message=/\d+/` used to match the
  Arabic-Indic digit `٣`. Write `\p{Nd}` for Unicode digits.
- Behind `extract kv`, a column of the DuckDB type TIMESTAMP compares as an
  instant
  ([ADR-0011](../adr/0011-field-repin-and-conflict-recovery.md), amended
  2026-11-09). With `trawl query --data`,
  `extract kv | where _time > "2026-11-01T06:00:00Z"` used to compare text
  and keep no rows.
- The live tail and the `extract kv` tail refuse an integer argument that is
  not an integer literal, such as `round(x, p)`, as stored search already
  did (ADR-0001, amended 2026-11-11).

Some stored text no longer parses. An ordered operator with a pattern
(`host<a*`), a regex that does not compile (`msg=/[/`, `msg=/*/`), and a `"`
right after a regex (`m=/x/"y"`) are now parse errors.

These rules also refuse stored text. The first three are fixed limits, with
no setting:

- One expression, or the search, is at most 64 levels deep. In a `where`
  stage, an `or` of 65 comparisons is refused with
  `expression is deeper than 64 levels`
  ([ADR-0024](../adr/0024-bind-time-expansion-budget.md), amended
  2026-11-11).
- Brackets or `NOT`s nested more than 512 deep in the raw text are refused
  before parsing. A bracket pair that holds a `"`, `/`, backtick, or `#`
  counts as still open, so 513 groups such as `(host="web-1" path=/api)`
  joined by `OR` are refused too.
- One `sort` or `dedup` stage names at most 64 fields, repeats included.
- Validation, saving, and every run check each call in every stage: its
  name, its argument count, and its literal arguments (ADR-0001, amended
  2026-11-11). `where match(message, "x")` used to pass `/api/v1/validate`
  and save, and failed only when it ran.
- An expression reads `AND`, `OR`, and `NOT` in capitals as operators
  ([ADR-0061](../adr/0061-formatting-never-changes-what-a-query-means.md),
  amended 2026-11-09). So `where NOT == 1` no longer reads a field named
  `NOT`. Write `` `NOT` `` to keep the field.

A stored query that breaks one of these rules fails its next validation or
scheduled run with the diagnostic. Its schedule stays enabled.

1.0 adds one app-state migration, `20261111000001_schedules_due_idx`. A 0.9
trawld refuses to start against a database that holds it (ADR-0018, amended
2026-11-11). So, before the upgrade, take a full backup of every
installation exactly as the
[backup and restore guide](../src/content/docs/operate/backup-restore.md)
says. A dump of the app-state database alone is not enough, because it does
not match a corpus that 1.0 has since written to. To roll back, install the
old release and follow the guide's "Restore on another host" section. It
starts from empty `trawl` and `fleet` databases and no data directory, so a
rollback on the same host first needs both databases recreated empty and
the data directory moved aside. The guide's note on a `fleet` database
that other Fleet applications share applies too. After the
upgrade, review saved queries, schedules, and investigation steps for the
spellings above.

## Clients written before 1.0

[ADR-0051](../adr/0051-the-web-ui-shows-instants-in-a-chosen-zone-and-computes-in-utc.md),
amended 2026-11-08, makes the display zone presentation in every client.
trawld and the embedded executor answer every query in UTC.

- `POST /api/v1/query` no longer has a `timezone` field. trawld ignores the
  field when an older client still sends it, and answers in UTC. A script
  that asked for another zone now gets `Z` timestamps.
- `ui.timezone` sets the zone in which the CLI, the TUI, and `trawl mcp`'s
  `orient` show instants. Its default, `local`, now means the zone of the
  machine that runs the client, read at each instant, so it follows daylight
  saving time. Before, `trawl query` and the TUI's batch results showed the
  trawld host's zone at one offset per query, while the live tail showed the
  client's zone.
- `ui.timezone` accepts `UTC` and `local` in any case, or a fixed offset
  `+HH:MM` or `-HH:MM` with two digits each. Any other value is a usage
  error before `trawl query` sends a request, before the TUI starts, and
  before `trawl mcp` serves. `trawl query --format parquet` prints no
  timestamps and does not read `ui.timezone`. Before, trawld accepted looser spellings such as
  `+5:30`, refused other values with 400, and the live tail showed UTC.

These API changes also reach clients:

- `POST /api/v1/saved/{id}/run` (**Run now**) and
  `GET /api/v1/saved/{id}/runs/{run_id}` need `query` as well as
  `saved_query`. A key with `saved_query` alone gets 403 `forbidden`, and the
  web UI does not show it **Run now** or the run rows
  ([ADR-0018](../adr/0018-retention-and-report-window-policy.md), amended
  2026-11-11).
- A manual run over its cap answers 429 `manual_run_busy` with an advisory
  `Retry-After`, and claims nothing. A key that presses **Run now** again
  while its own run of that net is in progress gets this 429, not the 409
  it got before. trawl-client does not retry it on its own.
- A schedule's `max_runs` above 9223372036854775807 answers 400
  `bad_request`. Before, trawld stored 9223372036854775807.
- A cancel by id, `DELETE /api/v1/queries/{id}`, now reaches a query, an
  export, or a capture that still waits to start. The cancel answers
  `cancelled: true`, and the cancelled request answers 503
  `service_unavailable` with `server at capacity: the query was not
  started`. Before, the cancel answered `cancelled: false` and the work ran
  later.
- `/api/v1/stream` answers a bad call with 400 `validation_error` and its
  hint, not `bad_request`. A bad call after `extract kv` loses the
  `post-processing:` prefix.
- `PATCH /api/v1/investigations/{id}` answers
  `{investigation, entry, activity}`, not the bare investigation. It and
  `PUT /api/v1/investigations/{id}/findings/{seq}/status` take an optional
  `seen_seq`, and answer `activity` only when it is sent. Upgrade trawld,
  `trawl`, and trawl-web together.
- An evidence budget refusal keeps 409 `evidence_budget_exceeded`, but its
  message now names the budget, the investigation's or the installation's.
  The `capture_refused` event logs that budget as `scope`.
- trawl-web answers its own refusals only with the error envelope,
  `{"error": {"code": ..., "message": ...}}`. The bare `{"error": "..."}`
  body is gone. Saved-query names have two new codes, 400 `invalid_name`
  and 409 `duplicate_name`
  ([ADR-0066](../adr/0066-the-spa-reads-every-failure-through-one-envelope-decoder.md)).
- In `trawl mcp`, `read action=page` takes a `columns` list, and the
  activity mirror's `more` is now `trawld_holds_more`.
- trawld's own retained events log `error_class` and `cause_kind` where they
  logged the text of a store, auth, engine, or I/O error. A saved query or
  an alert over `service=trawld` that reads that text finds the closed
  fields instead. Events stored before the upgrade keep their text until
  retention removes them.

These client changes store nothing new. The backup under
[Query text written before 1.0](#query-text-written-before-10) covers the
upgrade.

## Release coherence checklist

Nobody has run this checklist for v1.0.0. It has two groups:

- **Before the tag.** These steps gate the human's authorization to push the
  `v1.0.0` tag. Pushing the tag publishes every channel and the announcement.
- **After publication.** These steps verify the published channels and anchor
  Coastwatch. Everything they check is already public.

Run the steps in order, and record each result in the
[readiness ledger](1.0-readiness.md). Every step that creates a tag, a commit
on `main`, or a publication needs the human's authorization by name.

### Before the tag

The release commit is the commit that the tag will name. It is the version
commit from step 1, or the announcement commit from step 5 when that step adds
one. Steps 2, 3, and 4 must pass at the release commit itself. If step 5 adds a
commit, run steps 2, 3, and 4 again at that commit.

1. With the human's authorization, prepare the version in one commit on
   `main`, as `chore(release): prepare v0.9.2` did: the workspace version in
   `Cargo.toml`, `Cargo.lock`, and `crates/trawl-core/fuzz/Cargo.lock`, the
   TUI snapshots that print the version, and the `CHANGELOG.md` entry.
   `check-release-source.py` refuses a tag whose committed Cargo and lockfile
   versions differ from it.
2. Confirm that `ci.yml` and `distribution-preflight.yml` passed at the
   release commit. A push to `main` always starts `ci.yml`. A change to
   `Cargo.toml` or `Cargo.lock` starts `distribution-preflight.yml`, so the
   version commit starts it. A commit that changes only `docs/` does not.
   For such a commit, the runs in step 4 take the place of
   `distribution-preflight.yml`, because it calls the same two workflows.
3. Get a passing `docs.yml` run at the release commit. The `docs.yml` push
   trigger has a path filter, and a version-only commit matches none of its
   paths, so no run starts on its own. While the release commit is the head of
   `main`, run `gh workflow run docs.yml --ref main`. Confirm that the run's
   head SHA is the release commit.
4. Dispatch `linux-distribution.yml` and `macos-cli.yml` by hand with the
   release commit as `source-sha` and `tooling-sha`, and `v1.0.0` as
   `release-tag`. A manual run publishes nothing and creates no tag. Its
   `deb-x86_64-unknown-linux-gnu` artifact holds the packages for step 5.
5. Install Trawl on a clean Debian 13 amd64 host from the packages that step 4
   built at the version commit. Follow
   [Install from APT on Debian or Ubuntu](../src/content/docs/getting-started/index.md#install-from-apt-on-debian-or-ubuntu),
   but install the downloaded files instead of the repository's packages:
   `sudo apt install ./trawl-runtime_*.deb ./trawl-cli_*.deb ./trawl-server_*.deb`.
   Then follow the deployment guide through
   [Verify the installation](../src/content/docs/operate/deployment.md#verify-the-installation).
   Record the transcript and the result under `docs/launch/evidence/`. If the
   walk passes, add Debian 13 to the tested platforms in
   `docs/releases/v1.0.0.md`, and commit that change with the evidence before
   the tag. That commit changes no packaged file, so the walk stays valid for
   it. If the walk fails, the announcement names only Debian 12 and
   Ubuntu 24.04, and the ledger records the failure.
6. Confirm that `docs/releases/v1.0.0.md` at the release commit is the
   reviewed announcement. `release.yml` `build-chart` publishes those
   committed bytes and fails when the file is missing or empty.

When steps 1 to 4 and 6 pass at the release commit, and step 5's walk is
recorded in the ledger with the announcement matching its outcome, the human
decides whether to authorize the tag. A failed Debian 13 walk does not block
the tag. With that authorization, push the tag `v1.0.0` at the release commit.
`release.yml` runs `resolve-source.py`, builds and verifies every channel,
pushes the image, publishes the chart, runs `anonymous-pull.yml`, creates the
GitHub Release from the announcement, and then publishes the docs and the APT
repository.

4. Exercise the stable-site publish gate. `publish-docs` in `release.yml`
