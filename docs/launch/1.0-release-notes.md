## Current capabilities

Trawl collects and searches logs for homelabs and small installations on one
node. It stores events in Parquet and executes a pipeline query language with
DuckDB. The browser, CLI, and terminal UI provide access to server queries.
The CLI can also query local Parquet files without a server.

The current implementation provides these capabilities:

- HTTP ingest and optional native syslog listeners, with Vector integration examples.
- Filters, aggregations, field inspection, live queries, and result export.
- Saved query text, scheduled reports, and stored run results. A saved query does
  not freeze its current results.
- Role-based access through Fleet keys and browser sessions.
- A field catalog, retention controls, health metrics, and backup and recovery procedures.

These statements describe the source revision above. They do not establish
which downloaded release contains each capability.

## Requirements and limits

A server installation needs persistent storage and PostgreSQL for the Fleet
keystore and Trawl app-state databases. `trawld` owns ingest, storage, queries,
and the HTTPS API. `trawl-web` serves the browser UI and requires an API
connection, a public origin, and a persistent session key. Clients need
credentials with the required permissions and trust in the server TLS certificate.

Trawl has no clustering, sharding, or multi-tenancy. There is no published
hardware minimum or general throughput guarantee. Memory and storage needs
depend on the ingest rate, retention window, and queries. A single-node
installation needs its own backup and restore plan.

The repository contains Debian packaging, Linux archives, container and Helm
deployment paths, and source-build instructions. The final supported channel
and platform list needs release verification. Packaging code alone does not
prove that an artifact installs or runs on a clean host.
