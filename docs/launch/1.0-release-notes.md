## Current capabilities

Trawl collects and searches logs for homelabs and small installations on one
node. It stores events in Parquet and executes a pipeline query language with
DuckDB. The browser, CLI, and terminal UI query the server. The CLI can also
query local Parquet files without a server.

At `b3dc9121`, `main` provides these capabilities:

- First run: `trawl trial up` starts a disposable trial in Docker on Linux,
  with sample data, and `trawl trial down` deletes it
  ([ADR-0045](../adr/0045-first-run-is-a-trial-the-cli-owns.md)).
- Ingest: HTTP ingest, an optional native syslog listener, and Vector
  configurations shipped under `/usr/share/doc/trawl-server/examples/vector/`
  and tested with Vector 0.57.0. Each shipped transform that derives
  `service` checks it against trawld's service-name rule and falls back to a
  marked `*-unidentified` name
  ([ADR-0053](../adr/0053-shipped-vector-configs-send-only-service-names-trawld-accepts.md)).
- Ingest preview: trawld canonicalizes a sample and reports each event's
  outcome, and stores nothing from the sample
  ([ADR-0049](../adr/0049-an-ingest-preview-canonicalizes-a-sample-and-stores-nothing-of-it.md)).
- Syslog time: an RFC 3164 timestamp with no offset is read in
  `[syslog] default_timezone`, in a per-peer zone from
  `[syslog.sender_timezones]`, or in UTC
  ([ADR-0050](../adr/0050-syslog-reads-zone-less-time-in-a-configured-zone.md)).
- Search: filters, field inspection, aggregations, a time chart, live
  queries, and export as CSV, JSON, or Parquet.
- Saved query text, scheduled reports, and stored run results. A scheduled
  report can run by hand. A saved query does not freeze its current results.
- Access: role-based access through Fleet keys and browser sessions.
  `trawl-web` always verifies trawld's certificate
  ([ADR-0048](../adr/0048-trawl-web-always-verifies-trawld.md)).
- Diagnosis: `trawl doctor`, `trawld --doctor`, and `trawl-web --doctor`
  each prove named checks from one place
  ([ADR-0047](../adr/0047-a-doctor-proves-named-checks-from-one-vantage.md)).
- Health: disk headroom and per-environment retention reach
  ([ADR-0042](../adr/0042-capacity-reads-as-retention-reach-not-a-countdown.md)),
  one `query_timing` event per query
  ([ADR-0046](../adr/0046-a-query-reports-its-phases-in-one-timing-event.md)),
  and one `http_failure` event per server failure
  ([ADR-0040](../adr/0040-every-server-failure-names-its-request-and-stage.md)).
- Alerts: a Prometheus rule pack of fifteen alerts, in
  `monitoring/prometheus/trawl.rules.yml` and as the chart's
  `PrometheusRule`.
- Storage: a field catalog, retention controls, and backup and restore
  procedures. A search counts each acknowledged event exactly once across
  compaction and restart
  ([ADR-0041](../adr/0041-an-acknowledged-event-is-counted-exactly-once-across-compaction-and-restart.md)).
  Ingest is admitted against hot-buffer capacity
  ([ADR-0043](../adr/0043-ingest-is-admitted-against-hot-buffer-capacity.md)).
  trawld keeps its stored data owner-only
  ([ADR-0052](../adr/0052-trawld-keeps-its-stored-data-owner-only.md)).
- Request limit: `[server] max_concurrent_requests`, 32 by default, counts
  requests in progress across the listener. A request over it gets 503
  `request_limit_reached` at once. Probes have an allowance of 3, and query
  listing and cancellation an allowance of 4
  ([ADR-0054](../adr/0054-trawld-counts-requests-in-progress-against-one-server-wide-limit.md)).

These statements describe the source at `b3dc9121`. The selected release
commit must pass the checklist below before the announcement is published.

## Requirements and limits

A server installation needs persistent storage and PostgreSQL for the Fleet
keystore and Trawl app-state databases. The deployment guide tests PostgreSQL
17 and 18. `trawld` owns ingest, storage, queries, and the HTTPS API.
`trawl-web` serves the browser UI and requires an API connection, a public
origin, and a persistent session key. Clients need credentials with the
required permissions and trust in the server TLS certificate.

Trawl has no clustering, sharding, or multi-tenancy. There is no published
hardware minimum or general throughput guarantee. Memory and storage needs
depend on the ingest rate, retention window, and queries. The request limit
bounds ingest body memory at `max_concurrent_requests` × (wire body + decoded
body), 1 GiB at the defaults, plus 512 MiB for argon2 checks. A single-node
installation needs its own backup and restore plan.

## Chosen launch contract

A Trawl 1.0 installation starts with fresh Trawl application state and a fresh
shared Fleet keystore. Startup refuses incompatible existing state and does
not change it. [ADR-0036](../adr/0036-fresh-state-launch-baseline.md)
records this decision. Coastwatch is anchored to a Trawl revision through
`TRAWL_REV` in its CI. It pins `cdd12a5c`, and the anchor to the 1.0 release
commit is still open.

The platform target is a Linux server and CLI on amd64 and arm64, with a
Debian 12 floor, and a macOS CLI on macOS 15 or newer for Apple silicon and
Intel. The chart supports `tls.mode` `auto`, an existing TLS Secret
(`secret`), and a Certificate from an installed cert-manager issuer
(`certManager`). Each platform and chart mode has a CI check in the table
above or in `chart/trawl/tests/`.

The repository, release assets, container image, and chart are public.
`anonymous-pull.yml` checks anonymous access to the image and chart on
every release.

## Release coherence required before publication

Nobody has run this checklist for v1.0.0. Run the steps in order, and record
each result in the [readiness ledger](1.0-readiness.md). Every step that
creates a tag, a commit on `main`, or a publication needs the human's
authorization by name.

1. Pick the release commit on `main`. Confirm that `ci.yml`, `docs.yml`, and
   `distribution-preflight.yml` passed at that exact SHA.
2. Confirm that `docs/releases/v1.0.0.md` at that commit is the reviewed
   announcement. `release.yml` `build-chart` publishes those committed bytes
   and fails when the file is missing or empty.
3. With the human's authorization, prepare the version in one commit, as
   `chore(release): prepare v0.9.2` did: the workspace version in
   `Cargo.toml`, `Cargo.lock` and `crates/trawl-core/fuzz/Cargo.lock`, the TUI snapshots that print the version,
   and the `CHANGELOG.md` entry. `check-release-source.py` refuses a tag
   whose committed Cargo and lockfile versions differ from it.
4. Optionally, dispatch `linux-distribution.yml` and `macos-cli.yml` by
   hand with that commit as `source-sha` and `tooling-sha` and `v1.0.0` as
   `release-tag`. A manual run publishes nothing and creates no tag.
5. With the human's authorization, push the tag `v1.0.0`. `release.yml`
   runs `resolve-source.py`, builds and verifies every channel, pushes the
   image, publishes the chart, runs `anonymous-pull.yml`, creates the GitHub
   Release from the announcement, and then publishes the docs and the APT
   repository.
6. Record the artifact identities from that run: the SHA-256 of each
   tarball and `.deb`, the image digest for each platform of
   `ghcr.io/jakub/trawl:1.0.0`, the chart digest of
   `oci://ghcr.io/jakub/charts/trawl` version `1.0.0`, and the `source_sha`
   in `https://trawl.sh/release.json`. Each must name the release commit.
7. Verify each channel from outside the workflow:
   1. Debian: the APT `Packages` index for amd64 and arm64 lists
      `trawl-cli`, `trawl-server`, and `trawl-runtime` at `1.0.0-1`. Follow
      the installation guide's APT steps on a clean host, and check that
      `trawl --version` names the release commit.
   2. Helm: run `scripts/release/check-anonymous-pulls.sh v1.0.0` with the
      image and chart repositories, then follow the deployment guide's Helm
      install on a disposable cluster.
   3. Container: confirm that the image's
      `org.opencontainers.image.revision` label is the release commit.
   4. Linux archives: follow the installation guide's tarball steps on amd64
      and arm64, including the `.sha256` check.
   5. macOS archives: follow the same steps on macOS 15 for Apple silicon
      and Intel, including first-run approval.
   6. Docs site: `https://trawl.sh/release.json` shows `release_tag` `v1.0.0`,
      `channel` `release`, and the release commit as `source_sha`.
8. Exercise the stable-site publish gate. `publish-docs` in `release.yml`
   needs the `release` job, which needs `docker`, `publish-helm`, and
   `anonymous-pull`. Confirm in the run that `publish-docs` started only
   after `github release` succeeded. Confirm that a `docs.yml` build on
   `main` uploads an artifact whose `release.json` says `development` and
   deploys nothing.
9. Anchor Coastwatch: set its `TRAWL_REV` to the release commit and confirm
   that its CI passes.
10. Close the remaining ledger items with links to the release run and the
    checks above.

The workflow does not publish across services as one transaction. If the
GitHub Release, docs, or APT job fails after the image and chart are pushed,
rerun the failed jobs of that run.
