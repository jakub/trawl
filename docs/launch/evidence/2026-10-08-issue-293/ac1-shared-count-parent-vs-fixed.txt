## Reading

The edge tests use only parent-era APIs (with_edge_layers, HttpConfig, string literals),
so they compile against the parent and fail behaviourally, not at build time.

request_count_is_shared_across_routes_and_methods holds N=4 requests on GET /a, POST /a,
GET /b and PUT /b, then sends GET /c and expects an immediate 503 request_limit_reached.
On the parent, GET /c has its own semaphore of 4: it is admitted, enters its handler and
holds there, so the call does not answer within the 20 s deadline
("the response head arrived without waiting on a held request: Elapsed(())", edge.rs:71
via support.rs:270). That is the per-route-and-per-method budget the issue describes.

The other failures show the parent never refuses (waits instead of a 503) and exposes none
of the new metrics. response_bodies_and_streams_do_not_hold_the_count passes on both,
as expected: it only proves a response body does not hold a count.

The fixed-tree run of the same tests is at the end of this file.
