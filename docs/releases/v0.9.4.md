# Trawl 0.9.4

Trawl collects and searches logs for homelabs and small installations. Run one
Linux server, send it events over HTTP or syslog, and search them from a browser,
the command line, or the terminal UI.

This release adds an MCP server for AI agents, captured results, and shared
investigations. It also bounds the memory, disk, and CPU that one query can
use, and it fixes how the query language reads several filter spellings.

Read [Existing installations](#existing-installations) before you upgrade.
The API result format changed, two databases take migrations, and the chart
refuses some values that 0.9.3 accepted.

## What is included

- `trawl mcp --profile NAME` serves an MCP server over stdio for one saved
  profile. Its tools are `orient`, `fields`, `search`, `read`, `context`,
  `sightings`, `compare`, and `investigation`, and it serves the DSL reference
  as resources. It refuses `--url`, `--token`, and the matching environment
  variables, so an agent reaches only the server and key that the profile
  names. [Ask Trawl from Claude](https://trawl.sh/use/agents/) covers
  setup for Claude Code and Claude Desktop.
- A search can be captured as an immutable result that expires. Later reads
  page through the capture instead of running the query again.
  `POST /api/v1/results` creates one, and the new `[capture]` table sets its
  limits. `context`, `sightings`, and `compare` are correlation reads, and
  each one stores its answer as a capture.
- An investigation is a shared, append-only log of findings with kept
  evidence. Evidence outlives the corpus, within the clocks and budgets of the
  new `[investigation]` table. The web UI lists investigations in the sidebar.
  An open investigation polls while its tab is visible. **Keep row** in the
  result viewer adds a row as evidence, and **Send to investigation** in
  Search adds the current query. Two new permissions, `investigation_read` and
  `investigation_write`, gate this, and no existing role holds them.
- `GET /api/v1/capabilities` reports the server's version, limits, and DSL
  surface to any key with a Trawl grant.
- `[server] link_origin` sets the origin that trawld puts in front of every
  link to Search that it returns. trawld never derives the origin from the
  `Host` or `Forwarded` headers. With no value set, trawld returns no links.
- Spill files, hot snapshots, and export staging go to a scratch directory,
  `<data.path>.query-scratch`, with a size limit. `query_spill_max_bytes`,
  `query_memory_limit`, and `query_threads` bound one query's engine use. A
  query that runs out answers 503 `query_resource_exhausted`, and the server
  keeps serving. This is the fix for a single UI query that filled the pod's
  `/tmp` and got it evicted.
- Regex work is priced before the query runs, and regex memory has a
  per-query budget plus a server-wide reservation.
- Ingest sorts repairs into routine and actionable. Only actionable repairs log
  an `ingest_repairs` warning. `ingest_complete` counts both classes.
- The web UI has a clearer histogram scope line and colour key, a 24-hour ISO
  axis, filter-rail value counts, and a zero-result state that quotes the
  query.

## Fixes

### Query language

- `host!=web*` excludes the web hosts. An ordered comparison with a glob or
  regex, such as `host<a*`, is a parse error. A regex that does not compile is
  an error and is no longer matched as literal text.
- **Format** never changes what a query means. If it cannot keep the meaning,
  it refuses and leaves the text as you typed it.
- A field that the input does not carry reads as NULL in every execution
  path. Queries that failed with `unknown field`, or came back empty, now
  return what live tail returns.
- `extract kv` runs `sort` and `dedup` in the order you write them. `dedup`
  keeps the newest row for each key, and NULLs sort last in both directions.
- In bare-term text search, `_`, `%`, and `\` match themselves.

### Server

- A schedule's `max_runs` is a budget for its whole lifetime. Retention no
  longer refills it. `total_runs` counts every run the schedule has claimed,
  and the new `exhausted` field says when the budget is spent.
- Report retention deletes only finished runs, never running ones.
- trawld marks stale `running` report runs as `error` at boot.
- trawld writes a daily rollup in a durable order, behind a marker that
  records each file's size and BLAKE3 hash. Recovery uses those values to
  finish or abandon the rollup. If it cannot prove which, it stops and logs
  `rollup_recovery_unresolved` at ERROR, and `trawld --doctor` names the
  marker.
- The TCP and UDP syslog listeners keep running after an accept or receive
  error.
- The key audit reports every key change that it observes, including a key
  created and revoked between two polls. It retries a failed first snapshot
  and records an `audit_gap` event.
- A second repin request gets a 409 at once.
- trawld proves through bind mounts that its storage roots are apart. On
  Linux, it refuses to start when it cannot make that proof.
- Ingest caps each stored string value at 65,536 characters and records
  `field.truncated`.

### CLI, TUI, and trial

- The TUI **Saved** tab keeps a saved query's runs and results tied to that
  query.
- The TUI driver answers every execute when its query ends, and Ctrl+C
  cancels from search and column mode.
- An interrupted `trawl trial down` can be recovered. `trawl trial up` refuses
  while the teardown marker at `$XDG_STATE_HOME/trawl/trial.teardown` exists.

### Packaging

- The Debian Vector `base.toml` drops every journal field whose name starts
  with `_`.
- ctutils goes to 0.4.8 for RUSTSEC-2026-0385, a timing leak in the
  comparison that checks every session cookie. DuckDB goes to 1.5.6.

## Breaking changes for API clients

Every query result has a new format: query responses, report-run results, and
the stream's `data` and `snapshot` frames. Exports keep their own formats.

- Each column is `{name, type}`. The `type` is one of `boolean`, `integer`,
  `float`, `string`, `timestamp`, `date`, `time`, `list`, or `mixed`. A client
  must refuse a type that it does not know.
- Integer cells are decimal strings, not JSON numbers.
- Rows are arrays. A stream `data` frame is a one-row `{columns, rows}`.
- Timestamps are RFC 3339 with six fraction digits and an explicit offset.

The 0.9.4 CLI, TUI, and web UI read the new format. Older CLIs do not, so
upgrade them with the server.

A route now checks authority before it reads the request body. A JSON body
without its `Content-Type` gets a 400. trawld and trawl-web speak HTTP/1.1
only.

## Existing installations

0.9.4 keeps the 0.9.0 storage epoch. The server applies the app-database
migrations at startup. 0.9.3 cannot read what 0.9.4 writes, so a rollback
means restoring a backup.

### Back up first

1. Stop trawld cleanly.
2. Check that no `.rollup-*` file remains under the data root. 0.9.4 reads a
   0.9.3 rollup marker as unresolved, and reads of that day refuse until it
   is resolved. If a marker remains, start 0.9.3 again, let it recover, and
   stop it. [Resolve an unresolved rollup
   marker](https://trawl.sh/architecture/recovery/#resolve-an-unresolved-rollup-marker) has the steps.
3. With trawld stopped, run `pg_dump` on the app database and the auth
   database. Copy the data root, including `scheduled/`, at the same time.

### Databases

- The auth database gains the `investigation_read` and
  `investigation_write` permissions. trawld does not migrate that database.
  Run `fleet-admin migrate` from the 0.9.4 package. On Helm, the init
  container runs it.
- Upgrade every program that shares the auth database in the same window.
  An older fleet-admin or Coastwatch refuses a database that holds a
  migration it does not know.
- To use investigations, grant the permissions to a role, for example
  `fleet-admin roles add-perm trawl-reader trawl:investigation_read`.
  [Manage access](https://trawl.sh/operate/access/) lists the combinations.
- The schedule migration counts the runs that each schedule still has. A
  schedule whose older runs retention already deleted can run that many more
  times before it reaches its cap.
- A zero-row report run stored by 0.9.3 no longer decodes. Its detail shows
  no result, and `from saved` over it answers 500, until the schedule's next
  run replaces it.

### Configuration

Run `trawld --check-config` before you start 0.9.4.

- New `[server]` keys: `query_scratch_dir`, `results_dir`, `link_origin`,
  `query_spill_max_bytes` (`4GiB`), `query_memory_limit` (`2GiB`), and
  `query_threads` (4). The scratch and results directories default to
  siblings of `data.path`, so `data.path` needs a writable parent.
- New `[capture]` and `[investigation]` tables. The defaults are in
  `config/trawld.reference.toml`.
- Changed defaults: `[retention] min_free_disk_bytes` goes from `1G` to
  `6GiB`, `[ingest] compaction_memory_limit` from `2GB` to `1GiB`, and
  `max_concurrent_queries` is capped at 8. If your data volume has less than
  6 GiB free, pressure deletion starts as soon as 0.9.4 runs. Set
  `min_free_disk_bytes` before the upgrade to keep the old behaviour.
- `[scheduler] report_max_rows` is removed, and a config that sets it fails
  to load.
- trawld now refuses `report_retention_days` outside 1 to 36500,
  `max_runs_per_schedule = 0`, and a `data.path` or `ingest.wal_dir` that
  contains `..`.
- Stored queries can stop parsing under the query-language fixes above.
  Saved queries, schedules, and investigation steps keep their text. Open
  them after the upgrade and fix any that report a parse error.

### Helm chart

- The chart refuses `persistence.enabled=false`.
- The chart refuses a data root or a WAL directory outside `/var/lib/trawl`,
  and one that overlaps scratch, results, or the crash-dump mount. The
  default WAL stays at `{data.path}/wal`. If you moved `walDir` off the data
  volume, for example to an emptyDir, the upgrade does not render. To move
  the WAL back, stop the senders, wait for compaction to empty the WAL, back
  up the volume, then clear `walDir` and upgrade.
- The default memory request goes from 512Mi to 1Gi and the limit from 2Gi to
  8Gi. The trawl-web limit goes from 256Mi to 512Mi.
- `config.retention.minFreeDiskBytes` defaults to `6GiB`.
- New values: `config.server.queryScratchDir`, `resultsDir`, `linkOrigin`,
  `querySpillMaxBytes`, `queryMemoryLimit`, `queryThreads`,
  `config.ingest.compactionMemoryLimit`, `config.capture`, and
  `config.investigation`.
- `config.scheduler.reportMaxRows` is removed.
- The startup probe allows 5 minutes, and the termination grace period is
  `shutdownDrainSecs` plus 30 seconds.

### Debian

- `trawld.service` adds `LimitNOFILE=65536` and `MemoryMax=8G`.
  `trawl-web.service` adds `MemoryMax=512M`.
- If you copied the Vector configurations, copy `base.toml` again from
  `/usr/share/doc/trawl-server/examples/vector/`.

## Installation choices

| Platform | Available components |
| --- | --- |
| Linux amd64 and arm64 | Server and CLI archives, Debian packages, and container images |
| macOS 15 or newer, Apple silicon and Intel | CLI archives |
| Kubernetes | Helm chart for the Linux server and browser |

Linux packages target Debian 12. Archives include the DuckDB runtime. Keep
their `bin/` and `lib/trawl/` directories together. macOS archives use ad-hoc
signatures and are not Apple Developer ID signed or notarized.

Start with the [installation guide](https://trawl.sh/getting-started/) and
[your first query](https://trawl.sh/getting-started/first-query/).

## Requirements and scope

A server needs persistent storage and PostgreSQL, with separate databases for
authentication and application state. Clients need an API key with the required
permissions and trust in the server's TLS certificate. The browser requires
its own public origin and persistent session key.

Trawl is designed for one node. It does not provide clustering, sharding, or
multi-tenancy. Storage and memory needs depend on ingest volume, retention,
and queries.
