# Trawl 1.0

Trawl collects and searches logs for homelabs and small installations. Run one
Linux server, send it events over HTTP or syslog, and search them from a browser,
the command line, or the terminal UI. Events are stored in Parquet. The CLI can
also query local Parquet files without a server.

Start with [your first query](https://trawl.sh/getting-started/first-query/):
on a Linux machine with Docker, `trawl trial up` starts a disposable trial with
sample data, and the tutorial checks the same result in the browser and the
CLI. The [installation guide](https://trawl.sh/getting-started/) covers the
server packages. If someone already operates Trawl for you,
[connect to their server](https://trawl.sh/start/connect/).

## What you can do

- Collect application and system logs over HTTP, with the native syslog
  listener, or with the supplied
  [Vector configurations](https://trawl.sh/getting-started/vector-integration/).
  The Vector configurations are tested with Vector 0.57.0 and send only
  service names that trawld accepts. Journal events keep their systemd unit
  and syslog identifier. Events from the catch-all `/var/log` source keep
  their file name.
- Preview how trawld canonicalizes a sample event before you connect a
  sender. The [ingest preview](https://trawl.sh/operate/ingestion/#ingest-preview)
  stores nothing from the sample.
- Read syslog timestamps that carry no offset in a zone you choose with
  `[syslog] default_timezone`, or in UTC when it is unset.
- Filter events, inspect fields, calculate aggregates, chart counts over time,
  watch live results, and export results as CSV, JSON, or Parquet.
- Save query text for reuse, or schedule reports that keep their run results.
  Run a scheduled report by hand. Saving a query does not freeze its current
  results.
- Control access with API keys, roles, and browser sessions. trawl-web
  always verifies trawld's certificate, against the system roots or a pinned
  CA file.
- Check an installation from three places. `trawl doctor -p NAME` checks one
  client connection, `trawld --doctor --config PATH` checks the server host
  without changing it, and `trawl-web --doctor --config PATH` checks the
  browser proxy and its upstream.
  [Verify the installation](https://trawl.sh/operate/deployment/#verify-the-installation)
  shows how to run each one.
- Read disk headroom on the [Health page](https://trawl.sh/operate/health/),
  with how many days of its retention policy each environment is projected
  to keep.
- Find the slow phase of a query in its `query_timing` event. Each server
  failure names its request, route, and stage.
- Load the [operational alert pack](https://trawl.sh/operate/operational-alerts/)
  into Prometheus, or enable it in the Helm chart. It warns on discards,
  persistence and compaction failures, refused events, and search that stays
  refused.
- Manage field types, retention, and backups on one server.

A search counts each acknowledged event exactly once, across compaction and
restart. Right after a restart, a search either gives that count or answers
503 `corpus_recovering`. trawld keeps its data and write-ahead-log
directories owner-only.

## Installation choices

| Platform | Available components |
| --- | --- |
| Linux amd64 and arm64 | Debian packages from the APT repository and the release, tarballs with all five executables, and container images |
| macOS 15 or newer, Apple silicon and Intel | CLI tarballs |
| Kubernetes | Helm chart for the Linux server and browser |

The Debian packages are `trawl-cli`, `trawl-server`, and `trawl-runtime`,
which owns the shared DuckDB library. Tarballs include the DuckDB runtime;
keep their `bin/` and `lib/trawl/` directories together. macOS tarballs use
ad-hoc signatures and are not Apple Developer ID signed or notarized. See the
installation guide for prerequisites and first-run approval.

Before a release publishes anything, its build installs the Debian packages
and checks the tarball on Debian 12, for amd64 and arm64, with no network. It
also installs the server package on an Ubuntu 24.04 host that runs systemd.
It checks the installed macOS CLI on macOS 15 for each architecture. The
container image and the Helm chart pull without a registry login.

The Helm chart can keep trawld's generated certificate, mount an existing
TLS Secret, or request a Certificate from an installed cert-manager issuer.
The [deployment guide](https://trawl.sh/operate/deployment/#configure-the-daemon-api-certificate)
covers each choice.

## Requirements and scope

A server needs persistent storage and PostgreSQL, with separate databases for
authentication and application state. Clients need an API key with the required
permissions and trust in the server's TLS certificate. The browser requires
its own public origin and persistent session key.

trawld refuses a request over
[the request limit](https://trawl.sh/reference/configuration/#the-request-limit)
(`[server] max_concurrent_requests`, 32 by default) with 503
`request_limit_reached`.

Trawl is designed for one node. It does not provide clustering, sharding, or
multi-tenancy. Storage and memory needs depend on ingest volume, retention,
and queries. Use the [backup and restore guide](https://trawl.sh/operate/backup-restore/)
to protect an installation.
