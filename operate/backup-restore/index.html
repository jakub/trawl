Manual for Trawl v0.9.4. Build identity.

Back up and restore

A backup has three parts: the trawl database, the fleet database, and the state directory. Take all three while trawld is stopped. The catalog in the trawl database and the data/CATALOG marker must match, and report runs refer to files under the state directory. A copy of the Parquet files alone is an export, not a backup.

This page covers a Debian host with the packaged layout. On Kubernetes the order is the same: scale the StatefulSet to zero, snapshot the PVC, and dump both databases before you scale back up. A PVC snapshot alone is not a backup.

What to back up

Section titled “What to back up”
Part Contents Tool
trawl database Field catalog, query history, saved queries, schedules, report run records, captured result records pg_dump
fleet database API keys and roles, shared with other Fleet applications pg_dump
/var/lib/trawl data/ with the Parquet files, wal/, scheduled/, EPOCH, CATALOG, and any repin state. data.results/ with the captured result files. web.cookie. tls/ and tls-key/ when trawld generated the certificate tar
/etc/trawl, /etc/default/trawld, /etc/default/trawl-web Configuration, DSNs, and environment tar

Leave out /var/lib/trawl/cores. A crash dump is a copy of process memory.

The results root, data.results, sits beside the data root. It holds captured results, which expire 15 minutes after they are made, [capture] ttl_secs. Archive it in the same stopped window as the trawl dump, so that each capture’s file and its record come from one moment. A results_dir outside /var/lib/trawl needs its own path in the tar command below. The fleet dump and web.cookie are credentials, so encrypt the backup and keep it private.

Run a file-level backup or restore of /var/lib/trawl as the trawl user or as root. The data root and everything beneath it are owner-only, so a member of group trawl, such as trawl-web, cannot read them. A backup agent that runs as another user cannot make a complete backup. As a member of group trawl it can read web.cookie and tls/cert.pem, but none of the stored data. On Kubernetes, the mover must run as trawld’s uid, podSecurityContext.runAsUser in the chart, 1000 by default.

Restore on another host

Section titled “Restore on another host”

You need the same Trawl package installed with both services stopped, empty trawl and fleet databases owned by their login roles as in Provision the databases, their DSNs in TRAWL_DATABASE_URL and FLEET_DATABASE_URL, and no /var/lib/trawl/data directory. Keep the senders away from the host until the restore is verified.

Restoring the fleet dump into a database that other Fleet applications use reverts every key and role change made since the backup. For a shared database, restore the trawl dump only and reconcile keys by hand.

  1. Verify the files:

  2. Restore both databases:

    --single-transaction rolls a failed restore back. If one fails, fix the cause and run it again against the still-empty database.

  3. Extract the files and reapply the packaged modes:

    The archive replaces the package-generated web.cookie with the backed-up key, so browser sessions and shared Fleet sessions keep working.

    The restored data root must be owned by the user that runs trawld, trawl on a Debian host. tar as root restores the archived owner by name, so the packaged user gets it right. If trawld runs as another user on this host, run chown -R on /var/lib/trawl/data and /var/lib/trawl/data.results to that user before you start trawld. Do the same for /var/lib/trawl/tls and /var/lib/trawl/tls-key if they exist. They exist only when trawld generated its own certificate. trawld refuses to start on a data root, results root, or TLS directory owned by another user, and its error names the path, the owner, and the fix.

  4. Edit the restored configuration for this host: the DSNs in /etc/default/trawld, http_addr, the TLS paths, and public_origins. Keep [data] path unchanged. Set [scheduler] enabled = false so restored schedules do not run before you have checked the result.

  5. Compare the catalog marker with the database:

    The two UUIDs must be equal. If they differ, the dump and the archive come from different backups. Do not edit the marker.

  6. Start trawld, read its startup lines, then start trawl-web:

    Before it serves, trawld matches the results root against the restored capture records and logs the counts as results_reconcile. It removes files that no live capture names, marks live captures whose files are missing, and expires every temporary capture past its expires_at. A backup older than [capture] ttl_secs therefore restores no readable capture. A read of one answers 410 result_gone until its record ages out after [capture] tombstone_secs, counted from its expires_at. If the restored configuration has lower capture quotas than the backed-up server, trawld also prunes the oldest temporary captures of each key over them. It also prunes the kept evidence of every investigation whose retain_until has passed; the findings that cite it remain. Then it marks every investigation step that never recorded an outcome as interrupted and logs the count as investigations_boot. It also marks every report run left running as error with the message interrupted by server restart, and logs stale_runs_cleaned with the count when it marks any.

Verify the restore

Section titled “Verify the restore”

  1. Check health. Every check reads ok:

  2. Run the reference query from the backup directory and compare its output with reference.txt. Events that were still in the WAL become visible after the first compaction, within [ingest] compaction_interval_secs, 10 seconds by default.

  3. List the saved queries and report runs with GET /api/v1/saved and GET /api/v1/runs, or open them in the browser UI after you log in with a human key.

  4. Send one test event as in Send events over HTTP, restart trawld, and query it again. Exactly one row comes back.

  5. Set [scheduler] enabled = true, restart trawld, and reconnect the senders. A schedule with missed runs catches up on at most [scheduler] max_catchup_intervals intervals.

Keep the backup until the restored server has passed its normal checks.
