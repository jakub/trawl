What the mutation does is forget the StreamLifecycle handle in the
component's on_cleanup, and what makes that observable is WHICH path
closes the EventSource on unmount. There are two: the explicit
on_cleanup, and the live-tail Effect, which re-runs when the rail link
changes the router location and clears the same slot before returning
early. If the effect re-runs before the component is disposed, the
stream closes anyway and the mutation is invisible; if disposal wins,
the forgotten handle leaks and the spec sees `opens` climb. That order
is leptos's effect scheduling against owner disposal, not anything the
spec or the app states, so the kill was always a race — it happened to
land one way at 22:53 and the other way now.

The app behaviour is unchanged and correct in both directions: on the
unmutated tree both teardown tests pass, the EventSource closes and the
16ms render timer is released. What is lost is the PROOF that the
explicit cleanup is the thing doing it. Making that deterministic means
changing how the live tail is torn down, which is a bigger change than
either commit here.
