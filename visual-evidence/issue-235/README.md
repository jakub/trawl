## Finding: accepted events are missing from search after a restart

`harness.mjs restart-probe` sets `compaction_interval_secs = 30`. It ingests 50 events for a fresh service and counts them with `service=<probe> last=15m | stats count()`. Before the restart the count is 50. After SIGTERM, 1 WAL file still holds the events. After the restart, the count by seconds since startup is 0 at 0 s, 50 at 31 s. All events are visible after 31 s, when the first compaction completes (2026-09-23T04:28:40.391047Z).

Cause: the hot buffer starts empty (`crates/trawl-server/src/state.rs:645`) and nothing loads the WAL into it. The compaction loop sleeps one interval before its first tick (`crates/trawl-server/src/ingest/compaction.rs:71`), and shutdown stops the loop without a final compaction (`compaction.rs:97-99`). A query in that window gets a 200 with rows missing, not an error. The default interval is 10 s. The same code is at base `ed3a2516`. This is not the #235 500. Each scenario waits until the events carried over from the previous scenario are visible before it starts its loop, and records that wait.

The scenario runs show the same gap: c started with 33,960 of 34,701 carried-over events visible, all after 5 s (compaction interval 5 s); e started with 602 of 1,210 carried-over events visible, all after 253 s (compaction interval 300 s); g started with 32,160 of 32,751 carried-over events visible, all after 10 s (compaction interval 5 s).
